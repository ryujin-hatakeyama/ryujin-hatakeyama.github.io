I only got around last week to listening to *Type Theory Forall*, Episode 62, in which Vladislav Zavialov talks about Dependent Haskell, and over the past few days I have been going back to a few points from the discussion and looking into them a little further. When the conversation turns to GHC's dependency analysis, Zavialov calls the assumption that the dependency graph should be built before type checking a “mental block”: “How do we build this graph? How do we discover the edges?” The answer, as he puts it, was that some of the dependencies required for kind checking cannot in general be recovered from lexical dependency analysis alone: “the solution was we cannot do that. Let's just do a retrying mechanism.” Looking at [GHC 9.14's implementation notes](https://downloads.haskell.org/ghc/9.14.1/docs/libraries/ghc-9.14.1-da80/src/GHC.Tc.TyCl.html) afterwards, I found that this is almost exactly what the compiler now does. The renamer still computes the lexical dependency graph of non-instance type and class declarations, whose SCCs determine the groups that are kind-checked separately, while dependencies on instances, which need not be represented by free occurrences in the declarations that require them, are left to the checking phase. GHC places each instance in a singleton group after the lexical SCCs and then makes repeated passes over the remaining groups, retrying groups that could not yet be checked after successful checks have extended the environment. The retry is therefore not an algorithm for discovering the missing edges and rebuilding the graph, but a way of avoiding the need to represent those non-lexical instance dependencies as edges in a precomputed dependency graph.

GHC's own note gives a small example:

```haskell
type family F a
type instance F Int = Bool

data R = MkR (F Int)
type Foo = 'MkR 'True
```

Here `Foo` contains no occurrence of `F`: it mentions only `'MkR` and `'True`. Yet `'MkR` expects an argument of kind `F Int`, whereas `'True` has kind `Bool`, so `Foo` can be kind-checked only once the family equation `F Int = Bool` is available. Its dependency on that instance is therefore real but non-lexical: it is mediated by the kind of `'MkR`, rather than by any occurrence of `F` in `Foo` itself. This is the small case in which the question “How do we discover the edges?” becomes concrete: the missing dependency is not present among `Foo`'s lexical dependencies at all.
